# Desktop browser autofill setup

This document explains how to install the desktop browser autofill MVP and connect it to the running KeyVault desktop app.

Scope of the current implementation:
- Browser extension source: `desktop/browser_extension/`
- Native messaging host templates and scripts: `desktop/native_host/`
- Dart native host entry point: `tool/native_host.dart`
- Running app bridge: local loopback server started by the Flutter desktop app

## Extension vs app vs native host

The setup has three separate pieces:

1. **Chrome extension** (`desktop/browser_extension/`): runs inside Chrome, reads the current tab URL, displays matching credentials, and fills the selected page form.
2. **Native messaging host** (`desktop/native_host/keyvault_native_host.sh` on macOS/Linux or the Windows `.cmd` launcher generated by `install_host_windows.ps1` -> `dart run tool/native_host.dart`): small local process launched by Chrome. Chrome can only talk to local applications through a registered native messaging host.
3. **KeyVault desktop app**: when open, it starts a local authenticated bridge and serves credential matches from the currently selected vault. Keep the app open and unlocked for the recommended flow.

The extension is not the desktop app. Installing the extension alone is not enough: Chrome must also know which native host it is allowed to launch.

## Recommended use

1. Start the KeyVault desktop app.
2. Unlock your vault in the app.
3. Open a login page in Chrome.
4. Open the **KeyVault Autofill** extension popup.
5. Click **Find credentials**.
6. Select a match and click **Fill this account**.

Fallback mode in the popup can access a vault directly by database path and password/key file, but the recommended desktop flow is to keep the app open and unlocked.

## In-app onboarding

After unlocking a vault on macOS, Windows, or Linux, open:

**Settings → Tools → Desktop Chrome extension**

The in-app guide shows the extension folder, native host registration notes for the current desktop platform, a bridge connection check, and quick troubleshooting for host visibility, app state, extension linking, and manifest path/permissions.

## Install the Chrome extension

These steps are the same on macOS, Windows, and Linux during development:

1. Open Chrome and go to `chrome://extensions`.
2. Enable **Developer mode**.
3. Click **Load unpacked**.
4. Select this repository folder:

   ```text
   desktop/browser_extension
   ```

5. Copy the generated extension ID from the extension card. You need it when registering the native messaging host.

Optional packaging command from the repository root:

```bash
./desktop/browser_extension/package_extension.sh
```

This creates `desktop/browser_extension/dist/keyvault-browser-extension.zip`. Chrome's **Load unpacked** flow still expects the unpacked folder above.

## Register the native messaging host

The host name used by the current extension is:

```text
dev.camillobucciarelli.kdbxKeyVault_native_host
```

The host manifest must allow the exact Chrome extension ID generated by `chrome://extensions`.

### macOS

A macOS helper exists for development. From the repository root, run:

```bash
./desktop/native_host/install_host_macos.sh chrome <EXTENSION_ID>
```

Replace `<EXTENSION_ID>` with the ID copied from `chrome://extensions`.

The script writes:

```text
~/Library/Application Support/Google/Chrome/NativeMessagingHosts/dev.camillobucciarelli.kdbxKeyVault_native_host.json
```

It uses the template:

```text
desktop/native_host/manifests/chrome/dev.camillobucciarelli.kdbxKeyVault_native_host.json
```

and points Chrome to:

```text
desktop/native_host/keyvault_native_host.sh
```

### Windows

A Windows current-user helper exists for development. It does not require admin rights. From PowerShell in the repository root, run:

```powershell
.\desktop\native_host\install_host_windows.ps1 -ExtensionId <EXTENSION_ID>
```

Replace `<EXTENSION_ID>` with the 32-character ID copied from `chrome://extensions`.

If script execution is blocked by the local PowerShell policy, run it for this process only:

```powershell
powershell -ExecutionPolicy Bypass -File .\desktop\native_host\install_host_windows.ps1 -ExtensionId <EXTENSION_ID>
```

The script is idempotent and overwrites the generated files and registry value on each run. It writes:

```text
%LOCALAPPDATA%\KeyVault\NativeMessagingHosts\dev.camillobucciarelli.kdbxKeyVault_native_host.json
%LOCALAPPDATA%\KeyVault\NativeMessagingHosts\keyvault_native_host.cmd
%LOCALAPPDATA%\KeyVault\NativeMessagingHosts\keyvault_native_host.ps1
```

It uses the template:

```text
desktop\native_host\manifests\chrome\dev.camillobucciarelli.kdbxKeyVault_native_host.json
```

and registers this current-user Chrome registry value:

```text
HKCU\Software\Google\Chrome\NativeMessagingHosts\dev.camillobucciarelli.kdbxKeyVault_native_host = <manifest path>
```

The manifest points to the generated `.cmd` launcher. The `.cmd` starts the generated PowerShell launcher script without writing to stdout; that script keeps the repository root path with robust quoting, changes to that directory, and runs `dart run tool/native_host.dart`. Re-run the installer if you move the repository or Chrome changes the extension ID.

### Linux

Use the Linux user installer from the repository root:

```bash
./desktop/native_host/install_host_linux.sh <EXTENSION_ID>
```

Replace `<EXTENSION_ID>` with the ID copied from `chrome://extensions`.

The script is idempotent: rerunning it overwrites the current-user manifest with the latest host path and `allowed_origins` value. It does not require `sudo`.

By default the script writes the Chrome manifest to:

```text
~/.config/google-chrome/NativeMessagingHosts/dev.camillobucciarelli.kdbxKeyVault_native_host.json
```

It uses the template:

```text
desktop/native_host/manifests/chrome/dev.camillobucciarelli.kdbxKeyVault_native_host.json
```

and points Chrome to this launcher, making it executable if needed:

```text
desktop/native_host/keyvault_native_host.sh
```

Optional Chromium support is available when the extension is loaded in Chromium instead of Google Chrome:

```bash
./desktop/native_host/install_host_linux.sh --browser chromium <EXTENSION_ID>
```

This writes the same host manifest under:

```text
~/.config/chromium/NativeMessagingHosts/dev.camillobucciarelli.kdbxKeyVault_native_host.json
```

Manual Chrome registration, if needed for debugging:

1. Create the Chrome native messaging directory:

   ```bash
   mkdir -p "$HOME/.config/google-chrome/NativeMessagingHosts"
   ```

2. Create this manifest file:

   ```text
   ~/.config/google-chrome/NativeMessagingHosts/dev.camillobucciarelli.kdbxKeyVault_native_host.json
   ```

3. Use this content, replacing the absolute repository path and extension ID:

   ```json
   {
     "name": "dev.camillobucciarelli.kdbxKeyVault_native_host",
     "description": "KeyVault native messaging host",
     "path": "/absolute/path/to/password-manager/desktop/native_host/keyvault_native_host.sh",
     "type": "stdio",
     "allowed_origins": [
       "chrome-extension://<EXTENSION_ID>/"
     ]
   }
   ```

4. Ensure the launcher is executable:

   ```bash
   chmod +x /absolute/path/to/password-manager/desktop/native_host/keyvault_native_host.sh
   ```

For other Chromium-based builds using a different config directory, adjust the manifest destination according to that browser's native messaging host location.

## Verify connection

1. Confirm Dart is available to the native host:

   ```bash
   dart --version
   ```

2. Start the KeyVault desktop app and unlock a vault.
3. Confirm the app bridge config exists:
   - macOS/Linux: `~/.keyvault_autofill/bridge.json`
   - Windows: `%APPDATA%\KeyVaultAutofill\bridge.json`
4. Restart Chrome after changing native messaging registration.
5. Open `chrome://extensions`, enable extension error collection if needed, then open the KeyVault extension popup on a login page.
6. Click **Find credentials**. A working connection returns either matching credentials or `Found 0 credential(s)`; a native host registration problem usually shows `Specified native messaging host not found`.

## Troubleshooting

### `Specified native messaging host not found`

- Verify the manifest destination for your OS.
- Verify the manifest filename is `dev.camillobucciarelli.kdbxKeyVault_native_host.json`.
- Verify the manifest `name` is exactly `dev.camillobucciarelli.kdbxKeyVault_native_host`.
- Verify Chrome was restarted after registration.

### `Access to the specified native messaging host is forbidden`

- Verify `allowed_origins` contains the exact extension ID from `chrome://extensions`:

  ```text
  chrome-extension://<EXTENSION_ID>/
  ```

- If you reload the unpacked extension and Chrome changes the ID, re-register/regenerate the host manifest.

### `Native host has exited` or empty response

- Run `dart --version` in the same user environment.
- On macOS/Linux, verify `desktop/native_host/keyvault_native_host.sh` is executable.
- On Windows, verify `%LOCALAPPDATA%\KeyVault\NativeMessagingHosts\keyvault_native_host.cmd` and `keyvault_native_host.ps1` exist and that the repository path embedded in the `.ps1` file still exists.
- From the repository root, verify Dart can load the host entry point:

  ```bash
  dart analyze tool/native_host.dart
  ```

### `Running app session unavailable`

- Start the KeyVault desktop app.
- Unlock the vault in the app.
- Confirm the bridge config path listed in **Verify connection** exists.
- If the app has been open for a long time, retry after reopening the extension popup; bridge tokens rotate periodically.

### No credentials are filled

- Confirm the current page URL matches the saved credential URL/domain.
- Click **Find credentials** first, then choose **Fill this account**.
- Some custom login pages may not expose standard username/password fields; this MVP may need site-specific improvements.

## Security notes

- The popup does not persist the master password.
- The popup may persist fallback `databasePath`, `keyFilePath`, `limit`, and `autoRefresh` in extension local storage.
- Credentials returned to the extension are scoped by current tab URL/domain matching.
- The app bridge uses loopback and a short-lived bearer token stored in a local bridge config file.
- Do not paste vault passwords into browser storage or console logs.

## Current limits and follow-up

- macOS has a development install helper: `desktop/native_host/install_host_macos.sh`.
- Linux has a current-user Chrome/Chromium install helper: `desktop/native_host/install_host_linux.sh`.
- Windows has a current-user Chrome install helper: `desktop/native_host/install_host_windows.ps1`.
- The legacy files `desktop/native_host/install_mac.sh` and `desktop/native_host/com.cbucciarelli.keyvault.json` target an older host name and extension ID. Prefer `install_host_macos.sh` with the `dev.camillobucciarelli.kdbxKeyVault_native_host` templates for the current `desktop/browser_extension/background.js`.
- Safari and Firefox are out of scope for this Chrome-focused setup guide.
