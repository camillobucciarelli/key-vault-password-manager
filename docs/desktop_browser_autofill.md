# Desktop browser autofill v2 setup (safe MVP)

This milestone keeps the desktop/browser surface safe while the real vault/app
bridge is not wired yet.

Current scope:

- Browser extension source: `desktop/browser_extension/`
- Native messaging host templates and scripts: `desktop/native_host/`
- Dart native host entry point: `tool/native_host.dart`
- Protocol only: `hello`, `status`, `queryCredentials`, `revealForFill`

The extension/native host do **not** read `.kdbx` files, ask for the master
password, store browser settings, reveal credentials, or fill pages yet.
`queryCredentials` returns `app_bridge_unavailable` and `revealForFill` returns
`not_implemented` until a dedicated app/vault IPC and user-presence flow are
designed.

## Components

1. **Chrome/Edge MV3 extension** (`desktop/browser_extension/`): popup-only
   safe UI. It can check host status and, after a user click, send the active
   tab origin to `queryCredentials`.
2. **Native Messaging host** (`desktop/native_host/keyvault_native_host.sh` or
   the Windows launcher generated by `install_host_windows.ps1`): frame-by-frame
   stdio process that speaks protocol v2 and logs only redacted errors to
   stderr.
3. **KeyVault desktop app bridge**: not implemented in this milestone.

## Native host name

Chrome/Edge require a lowercase native host name. v2 uses:

```text
dev.camillobucciarelli.keyvault_native_host
```

Legacy host names such as `com.cbucciarelli.keyvault` and
`dev.camillobucciarelli.kdbxKeyVault_native_host` are disabled/removed.

## Install the extension

Development load steps are the same for Chrome and Edge:

1. Open `chrome://extensions` or `edge://extensions`.
2. Enable **Developer mode**.
3. Click **Load unpacked**.
4. Select this repository folder:

   ```text
   desktop/browser_extension
   ```

5. Copy the generated extension ID. Register the native host with that exact ID.

Optional package command from the repository root:

```bash
./desktop/browser_extension/package_extension.sh
```

## Register the native messaging host

### macOS

Chrome:

```bash
./desktop/native_host/install_host_macos.sh chrome <EXTENSION_ID>
```

Edge:

```bash
./desktop/native_host/install_host_macos.sh edge <EXTENSION_ID>
```

The script writes `<host-name>.json` under the browser's
`NativeMessagingHosts` directory and injects:

```text
allowed_origins: chrome-extension://<EXTENSION_ID>/
path: /absolute/path/to/desktop/native_host/keyvault_native_host.sh
```

### Linux

Chrome:

```bash
./desktop/native_host/install_host_linux.sh <EXTENSION_ID>
```

Chromium:

```bash
./desktop/native_host/install_host_linux.sh --browser chromium <EXTENSION_ID>
```

Edge:

```bash
./desktop/native_host/install_host_linux.sh --browser edge <EXTENSION_ID>
```

### Windows

Chrome:

```powershell
.\desktop\native_host\install_host_windows.ps1 -Browser Chrome -ExtensionId <EXTENSION_ID>
```

Edge:

```powershell
.\desktop\native_host\install_host_windows.ps1 -Browser Edge -ExtensionId <EXTENSION_ID>
```

The Windows helper writes the manifest and launchers under:

```text
%LOCALAPPDATA%\KeyVault\NativeMessagingHosts\
```

and registers the current-user Chrome/Edge registry key for the v2 host name.

## Protocol v2

Every native message is one frame:

```text
4-byte little-endian payload length + UTF-8 JSON object
```

Common request envelope:

```json
{
  "version": 2,
  "id": "request-id",
  "type": "status",
  "payload": {}
}
```

Supported request types:

- `hello`: returns host metadata, supported messages and safe-mode state.
- `status`: returns host available + app/vault bridge unavailable.
- `queryCredentials`: validates an http(s) URL/origin and returns
  `app_bridge_unavailable`; never returns credentials.
- `revealForFill`: validates `entryId` and returns `not_implemented`; never
  returns passwords.

The host rejects legacy secret-bearing fields (`masterPassword`, `password`,
`databasePath`, `keyFilePath`, `credentials`, etc.) with
`legacy_fields_rejected`.

## Verify

From the repository root:

```bash
dart analyze tool/native_host.dart tool/native_host_protocol.dart
flutter test test/tool/native_host_test.dart
node --check desktop/browser_extension/background.js
node --check desktop/browser_extension/popup.js
```

Manual browser check:

1. Register the native host for the loaded extension ID.
2. Restart Chrome/Edge.
3. Open the extension popup.
4. Click **Check host status**: host should be `Available`, app/vault bridge
   should be `Not connected`.
5. On an `https://` page click **Check current site**: the popup should show a
   safe `app_bridge_unavailable` message and no credentials.

## Firefox

Firefox is not implemented in this MV3 service-worker extension. Do not load the
Chrome/Edge manifest in Firefox. A separate Firefox manifest/background design is
required before Firefox support is advertised.

## Security notes

- The popup contains no master password, database path or key file fields.
- No extension storage is requested or used.
- No static content script, `scripting` permission or `<all_urls>` host
  permission is registered until a safe fill flow exists.
- The popup sends only the active tab **origin** to the local native host after a
  user click.
- Native host logs go to stderr and contain only redacted error codes, never
  payloads or secrets.
- Packaging a signed native host binary is still TODO; development launchers
  fall back to `dart <repo>/tool/native_host.dart` without writing to stdout.
